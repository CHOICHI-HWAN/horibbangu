# Windows 3.5.3 동작과 반복 실행 점검

3.5.2의 24fps 수동 CSS 재생을 제거했습니다. 모든 애니메이션을 조회·정지한 뒤 `currentTime`을 반복 대입하던 작업과 전역 MutationObserver도 제거했습니다. 기존 CSS 키프레임과 전환은 브라우저에서 직접 재생합니다. 고양이 위치는 최대 60fps로 갱신하며, 갱신 간격의 나머지를 보존하고 오래 밀린 프레임은 재생하지 않습니다.

숨김 시에는 CSS 재생을 스타일로 정지하고 고양이 프레임 요청을 멈춥니다. 복원 시 한 개의 프레임 루프를 재개합니다. 입력 영역 캐시, 호수·날씨의 픽셀 예산과 저빈도 시계·조명 갱신은 유지합니다. 원래 고양이 그림과 행동 패턴은 바꾸지 않았습니다.

## 검증 조건

`tests/desktop-lifecycle.cjs`는 macOS·Brave headless, 1440×900 화면에서 실제 브라우저 시계를 사용합니다. 1초마다 행동을 바꾸며 120초간 실행하고, 10초마다 최근 600프레임의 빈도·프레임 간격·DOM 요소·애니메이션 수와 강제 GC 이후 JS 힙을 기록합니다. 자연스러운 손님 방문에 따라 고양이 수가 늘 수 있으므로 DOM 누적 여부는 각 고양이와 방을 나누어 검사합니다.

이 검사는 항상 위에 전환 시 메뉴 표시, 메뉴 버튼·고양이 클릭으로 다시 열기, 세 차례 숨김·복원, 숨긴 동안 시계와 CSS 재생 정지도 포함합니다. `desktop/windows/native/test_interactive.py`는 Windows 실행파일에서 실제 마우스로 고양이·메뉴 버튼을 클릭하고 드래그와 빈 공간 클릭 통과를 검사합니다.

## 측정 결과

| 항목 | 시작 구간 | 마지막 구간 |
|---|---:|---:|
| 고양이 위치 갱신 | 58.80 fps | 58.73 fps |
| 프레임 간격 95백분위 | 25.1 ms | 25.0 ms |
| 강제 GC 후 JS 힙 | 2.704 MB | 2.747 MB |
| 고양이 수 | 8 | 11 |

120초 반복 행동 검사와 세 차례 숨김·복원이 통과했습니다. 손님 방문으로 고양이는 8마리에서 11마리로 늘었으며, 각 고양이 안의 요소 수는 일시적인 말풍선·음표 등으로 137~138개 범위에 머물렀습니다. 방 요소는 누적되지 않았습니다. 원본 측정은 실행 시 `build/desktop-lifecycle.json`에 저장됩니다.

`tests/frame-clock.cjs`는 60·120·144·240Hz와 불규칙한 간격에서 약 59~60fps를 확인했습니다. 중복 프레임 요청, 숨김 후 복원과 한 시간의 시계 점프에서도 단일 루프를 유지하고 밀린 프레임을 재생하지 않습니다. 이 마지막 검사는 실제 한 시간 실행을 의미하지 않습니다.

Windows 기본판·박박사판·김박사판의 [실제 실행 검사](https://github.com/CHOICHI-HWAN/horibbangu/actions/runs/40631729322)가 모두 통과했습니다. 고양이 클릭으로 메뉴 열기, 작은 메뉴 버튼의 실제 클릭과 화면 메뉴에서 네이티브 설정 열기, 공기방울 드래그, 빈 공간과 Explorer 아이콘 클릭, 트레이 팝업과 화면보호기를 검사했습니다. 배포 파일은 이 검사에서 실행한 EXE를 그대로 사용합니다.

## 해석의 한계

이 검사는 수 시간 연속 실행이나 사용자 Windows 11 24H2 PC의 재현 검사가 아닙니다. 3.5.2의 짧은 CPU 측정은 부드러움과 장시간 안정성을 보장하지 못했습니다. 3.5.3은 동작의 자연스러움을 우선하며, 더 높은 프레임률에 따른 CPU 비용이 있으므로 이전 버전의 CPU 감소율을 이 버전에 적용하지 않습니다.
